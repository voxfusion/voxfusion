## Cursor Cloud specific instructions

### Overview

VoxFusion is a Bun/Turborepo monorepo with two packages:

- `@voxfusion/app` — the desktop app: native Rust on GPUI, through the `gpui-kit` crate (pinned to `=0.7.0`). The product is **macOS-only**; the app also builds and runs on Linux, for interface work, with fallbacks for the macOS-only services.
- `@voxfusion/marketingsite` — Astro static marketing website.

`packages/app/src` layout: `app.rs` starts everything; `ui/` holds the windows; `backend/api.rs` is the interface between the windows and the services (the `Backend` trait, the data types, `AppEvent`); `backend/native/` implements it; `platform/` holds macOS integrations; `fixture.rs` is a canned-data backend for screenshots.

### Running services

| Service | Command | Port | Notes |
|---------|---------|------|-------|
| Desktop app | `cd packages/app && bun run dev` | — | Needs a display. On macOS `scripts/dev.sh` runs the debug build as a signed bundle through LaunchServices, so that macOS permissions work (see Gotchas). On Linux it is `cargo run`: no microphone permissions, tray, or Metal |
| Desktop app, canned data | `cd packages/app && VOXFUSION_FIXTURE=scenario.json cargo run --features fixture` | — | See "Checking the interface" below |
| Marketing site (Astro) | `cd packages/marketingsite && bun run dev -- --host 0.0.0.0` | 4321 | Fully functional on Linux |

### Lint / typecheck / build

- `bun run check` — runs Biome across the repo (the marketing site; the app is Rust).
- `cd packages/app && cargo check --all-targets && cargo test` — the app. Also `cargo check --features fixture`.
- `bun run --filter @voxfusion/marketingsite typecheck` — runs `astro check`.
- `bun run build` (from `packages/marketingsite`) — builds all 6 static pages successfully.
- `packages/app/scripts/bundle-macos.sh` — builds `VoxFusion.app` (macOS only; see the script's header).

### Rust on Linux

The whole crate builds on Linux: `whisper-rs` uses `metal` only on macOS, and the macOS-only modules are behind `cfg(target_os = "macos")` with fallbacks. `cargo test` runs everything except the tests that need AppKit types.

macOS-only code cannot be compiled here in full (GPUI's macOS backend, CoreAudio bindings and whisper's Metal backend need a Mac), but it can be type-checked: put the files in a scratch crate (include them with `#[path = "..."]`) whose dependencies are the pure-Rust bindings (`objc2*`, `core-foundation*`, `block2`, `dispatch2`, `tray-icon`), and run `cargo check --target aarch64-apple-darwin`. Checking does not link, so no macOS SDK is needed. Keep macOS-only files free of GPUI types where possible so they stay checkable this way (`platform/overlay_window.rs`, `platform/activation.rs`, `tray.rs`). CI runs the real `cargo check` and `cargo test` on macOS.

### Checking the interface

With `--features fixture`, `VOXFUSION_FIXTURE=<file>` runs one window against canned data instead of the real services, with animations held at their first frame and the caret hidden. The file is JSON: `{ "theme": "light", "window": "main" | "voice-control", "route": "/dictionary/per-app", "size": [1360, 850], "fixture": { ...see FixtureData in src/fixture.rs... } }`. JSON lines on stdin script it: `{"type":"emit","event":"model-download-progress","payload":{...}}` (any `AppEvent`, by its serialized name), `{"type":"updateEvent","message":{...}}`, `{"type":"shortcut","shortcut":"Escape","state":"Pressed"}`, `{"type":"wheel","x":..,"y":..,"dy":..}`.

To screenshot it on a headless Linux machine: start `Xvfb :N -screen 0 <w*2>x<h*2>x24`, run the app with `DISPLAY=:N GPUI_X11_SCALE_FACTOR=2 TZ=UTC`, find the window with `xdotool search --onlyvisible --class voxfusion`, move it with `xdotool windowmove <id> 0 0` (GPUI places X11 windows 2px right of the requested origin), drive it with `xdotool mousemove/click/type/key`, and grab the screen with `import -window root`. Rendering goes through Vulkan's software driver (lavapipe); the `DRI3` warnings are harmless. Wait until two consecutive grabs are identical before sending input or taking the final shot: on a busy machine the first frames can take seconds.

The interface was ported from a Tauri/SolidJS frontend (last commit with it: `c11be28`) with before/after screenshot comparison of every state. If you need that reference again, check out that commit, run its Vite dev server with `window.__TAURI_INTERNALS__` mocked, and screenshot it with Chromium launched with `--force-device-scale-factor=2` (an emulated scale factor snaps boxes to CSS pixels instead of device pixels, unlike a real Retina display).

### Gotchas

- Railway builds the marketing Dockerfile from the repository root. Keep `packages/app/package.json` available in `.dockerignore`; the workspace lockfile requires it even when building only the marketing site.

- The marketing site's English strings live in `packages/marketingsite/src/i18n/ru/`; `translations.ts` maps those modules to the `en` locale despite the directory name. The homepage waveform uses deterministic heights and unitless animation scales; percentage values are invalid for `scaleY()`.

- The marketing site is served from `voxfusion.io` (Railway project `voxfusion.io`, redeployed on every push to `main`). `voxfusion.com` has no DNS records, so canonical URLs, the sitemap, Open Graph tags, and contact addresses must use `.io`. Fonts are self-hosted through `@fontsource-variable/jetbrains-mono`; the site should make no third-party requests besides Umami.

- Landing page blocks marked `data-reveal` fade in on scroll (`BaseLayout.astro`); the hidden state is gated on `html.js`, so they stay visible without JavaScript. The reveal is a `backwards`-filled animation, not a transition, so a component's own `transition` or hover `transform` cannot collide with it; stagger siblings with `--reveal-delay`, and key child effects off the ancestor's `.is-visible`. Astro adds its scope attribute to every compound selector, so a scoped `.table tbody td` outranks `.table .modifier`. Umami's `data-umami-view` fires at 30% visibility, which a tall section never reaches on phones; put it on the section intro. When scripting full-page screenshots, scroll with `behavior: "instant"`: the site's `scroll-behavior: smooth` makes repeated `scrollTo` calls go nowhere, leaving reveal blocks blank. Emulate `prefers-reduced-motion: reduce` to capture every animation in its finished state.

- Typed-text effects on the landing page go through `src/scripts/typewriter.ts`, which keeps the untyped remainder in the flow (invisible) so lines never re-wrap mid-animation. That only covers one text; `HeroDemo.astro` cycles samples of different lengths, so every sample must still fit the `min-height` reserved for `.typed` and `.heard` at each breakpoint, or the hero changes height while the demo loops. Each animated block is server-rendered in its finished state for no-JS and reduced-motion visitors.

- `public/og.png` is rendered from `public/og.svg` at 1200×630 in a browser with JetBrains Mono loaded (the SVG alone falls back to a system font). After changing it, bump the `?v=` query in `Seo.astro`, because social networks cache the image by URL.

- Site copy must match what ships: the app requires macOS 11.0 (`LSMinimumSystemVersion` in `macos/Info.plist`, and `MACOSX_DEPLOYMENT_TARGET` in `release.yml`), Parakeet covers 25 European languages, styles only affect Whisper, and the updater asks before installing.

- Rust toolchain must be ≥1.85 (edition 2024 support). Run `rustup update stable && rustup default stable`.
- Parakeet supports dictionary biasing through CrispASR's `--hotwords` argument in the pinned engine. It does not support Whisper's prose style prompts. Resolve global/app/site vocabulary before engine dispatch and keep successful-recording retention in the shared transcription handler. Site icons are deliberately generated locally; external favicon services disclose configured domains.
- macOS gives permissions to an app bundle started by LaunchServices. A bare `cargo run` binary started from a terminal is held to the terminal's permissions: the microphone and Accessibility prompts name the terminal, and the System Audio Recording prompt never appears, so the muffle filter cannot be enabled. `bun run dev` (`scripts/dev.sh`) therefore runs the debug build as `VoxFusion Dev.app` (bundle id `io.voxfusion.app.dev`, data shared with the installed app) with `open`, tails its log, and quits it on Ctrl+C. It signs with the first "Apple Development" identity in the keychain, so grants survive rebuilds; with an ad-hoc signature (`SIGN_IDENTITY=-`, or no identity) the code hash is the identity, every rebuild is a new app to macOS, and the script resets the stale grants so macOS asks again. On a machine nobody can click on, the Apple Development identity blocks on a keychain prompt: use `SIGN_IDENTITY=-`. The app logs `started_outside_bundle` when it runs as a bare executable.
- For native QA, build a separate bundle with `BUNDLE_ID=io.voxfusion.qa APP_NAME="VoxFusion QA" scripts/bundle-macos.sh --debug` and run it with `VOXFUSION_APP_ID=io.voxfusion.qa`: the bundle identifier isolates macOS permissions, the environment variable isolates settings, SQLite history, models, logs, and the single-instance lock. An existing model file can be copied into that profile without copying personal history. `open -W <app> --args --permissions-report <file>` writes what macOS currently allows that build, and `--request-microphone` / `--request-audio-capture` bring up the prompts the way the app does (see `src/diagnostics.rs`); CI's `bundle` job checks both prompts on a GitHub runner by looking for a new `UserNotificationCenter` window. On that runner (macOS 15) a prompt stays on screen after the process that asked is killed, and the next prompt waits behind it; `killall UserNotificationCenter` closes it. Permission prompts and OS authentication may require the user to complete the system dialog.
- GPUI sets the `Regular` activation policy in `applicationDidFinishLaunching`, which overrides `Info.plist`'s `LSUIElement` and would show a Dock icon. `app.rs` calls `platform::activation::become_menu_bar_app()` first thing in the launch callback, in the same turn of the run loop, so the Dock never shows the icon. Accessory apps have no menu bar, so menu-bar-only actions also need a tray item. A GitHub `macos-15` runner can verify this without a Mac: `NSRunningApplication.activationPolicy` and `lsappinfo info -only ApplicationType` (`UIElement` vs `Foreground`), with `screencapture` and System Events available. A Dock icon without a running dot is the "recent apps" entry from an earlier Regular launch, not a running app.
- The Parakeet engine compile takes ~2h in CI, so releases depend on the `crispasr-engine-macOS-<build script hash>` cache existing on `main` (tag caches are invisible to other tags). GitHub evicts caches unread for 7 days, which silently made v0.9.12–v0.9.15 recompile it. `engine-cache.yml` now reads it daily, and both workflows restore the engine from the newest release built from the same `build-parakeet-engine.sh` (its app bundles carry the engine in `Contents/Resources/bin`) before compiling. Check with `gh cache list --key crispasr-engine` before tagging. The cache key is the hash of `build-parakeet-engine.sh` as a whole, comments included: any edit to that file, however cosmetic, costs a full engine compile, which is why its comments still mention the old Tauri paths. `bundle-macos.sh --engine-dir <dir>` puts the engine files in the bundle.
- `turbo dev` runs both packages' dev scripts concurrently (uses TUI mode).
- Production macOS logs are written to `~/Library/Logs/io.voxfusion.app/voxfusion.log` (`src/logging.rs`; one file, started over at 5 MB). Its timestamps are UTC even when macOS is in another timezone; correlate them with `log show`/wall-clock times accordingly. Dictation and its hotkeys are driven by an app-level entity (`ui/voice_control`), not by a window, so they do not depend on any window being alive or visible. Releases through v0.9.10 accumulated `PRESSED_KEYS` from transitions without resynchronizing after activation, screen lock, or sleep/wake; the watcher now rebuilds state from each event's modifier flags and logs `system_key_state_resynchronized` when it repairs a discontinuity.
- Modifier-only hotkeys must read the side-specific `NX_DEVICE*KEYMASK` bits from `NSEvent.modifierFlags` without masking off device-dependent flags. On this laptop, `CGEventSourceKeyState` reported `{LeftCommand}` for right Command events, so `RightCommand` hold-to-speak never matched. Polling live state during event delivery can also read ahead of queued events. Use `CGEventSourceFlagsState` only for startup/lifecycle snapshots, and event flags for transitions.
- The recording cues (`src/sounds.rs`) are the three cuelume sounds of the old web frontend, synthesized sample by sample and played through cpal; they were matched against the same recipes rendered by a browser's `OfflineAudioContext`. The output stream opens with the first cue and stays open. Play the start cue before microphone setup because `mute_media_for_recording` mutes the default output device and can cut off a cue scheduled immediately beforehand.
- Microphone hot-plugging: cpal 0.15's CoreAudio disconnect listener held a strong reference to its own stream, so streams on an explicitly selected mic were never dropped and their stale listeners kept calling the recorder's error callback. cpal 0.17 fixes that cycle, but it still ignores a disconnect of the device that is the system default input; the stream just stops delivering samples. The recorder therefore owns one id-tagged recording at a time and fails it from an input watchdog. It closes CoreAudio streams on a detached thread so a slow teardown of a just-removed device cannot wedge stop or the next start. In cpal 0.17, `description()` (and the deprecated `name()`) opens AudioUnits to count configs, so device enumeration is not free.
- "Mute media while recording" must unmute the device it muted, not whatever is the default output at restore time: plugging or unplugging a headset mid-recording moves the default. Devices unplugged while muted are unmuted when CoreAudio reports them again. The cue output is reopened after `AudioDevicesChanged` (`sounds::reset_output`).
- "Muffle media while recording" plays other apps' audio through a low-pass filter (`src/backend/native/media/filter.rs`, 4th-order Butterworth swept on a log scale from 20 kHz to 350 Hz), through the process tap in `tap.rs`, on every output. It falls back to lowering the default output's virtual main volume (`vmvc`, the value behind the system volume slider) through `AudioObjectGetPropertyData`/`SetPropertyData` in these cases: macOS before 14.2, System Audio Recording off (checked with the private `TCCAccessPreflight`: 0 granted, 1 denied, 2 not asked; a denied tap delivers silence), an aggregate output, or a Bluetooth headset whose microphone is recording. The `AudioHardwareService*` wrappers are deprecated. One worker thread in `media/muffle.rs` owns every volume, filter and tap change and fade, so the backend calls only post a message and cannot delay recording start. A tap session follows the default output when it changes mid-recording. Its state machine runs against a fake output in `cargo test`; on Linux, copy `muffle.rs` and `filter.rs` into a scratch crate with a stub `CoreAudioOutput` to run those tests. CoreAudio may apply volume changes asynchronously, so do not detect user volume changes by comparing read-back values: a false match would leave the output turned down.
- Many outputs have no `mute`, `vmvc`, or per-channel `volm` property at all, under any API (`AudioObject*` or `AudioHardwareService*`): USB audio interfaces with a hardware knob (Arturia MiniFuse) and DisplayPort/HDMI displays. CoreAudio answers `'who?'` (2003332927), and the macOS volume slider is greyed out for them. `media/tap.rs` handles these outputs with a process tap (macOS 14.2+, looked up at runtime). The tap covers the output's first stream, excludes the app's own process, and uses `CATapMutedWhenTapped`. A private aggregate device plays the tap back at a cubic gain; the tap is the last input buffer, after the output device's own inputs. A `CATapMuted` tap that nobody reads mutes nothing. Reading the tap prompts for System Audio Recording (`NSAudioCaptureUsageDescription`). If that permission is missing, the tap delivers silence but still holds the audio back, so muffle on these outputs mutes instead. Killing the process restores the audio at once. An Aggregate or Multi-Output Device used as the output cannot be nested in the playback device, which then has no output streams. Mute still works there, but muffle is refused instead of silencing the output.
- Measuring real output for audio QA: shell commands spawned by the agent host inherit its TCC identity, which has no microphone access, so input reads all zeros. Wrap the meter in a small ad-hoc signed `.app` with `NSMicrophoneUsageDescription` and launch it with `open`. In clamshell mode the built-in microphone is disconnected and also reads zeros. A narrowband 1 kHz detector on another microphone picks up the built-in speakers, and even headphone leakage, clearly. Every ad-hoc re-sign or rebuild changes the code hash, so macOS prompts again (microphone, System Audio Recording); batch rebuilds. Signing with the Apple Development identity blocks on a keychain prompt. In zsh, `log` is a shell builtin; use `/usr/bin/log show`. Synthesized key presses do not reach the dictation shortcuts. For scripted dictations, add a temporary trigger outside the commit: a thread watches a file and emits the hotkey's `AppEvent`s, which the dictation controller answers as it would the keys.
- System Audio Recording (`kTCCServiceAudioCapture`) quirks, all observed on macOS 26.5: inside the running app (observed with the Tauri build; not re-tested since the port to GPUI), reading a tap never brings up the prompt, while the same Rust tap code in any plain process does. The cause was not the bundle, Info.plist, signing, entitlements, callback style, thread, or activation policy. So `tap::request_permission` launches the app executable with `--request-audio-capture-permission <device UID>` to hold an unmuted tap until the prompt is answered, and reports the answer by exit code. TCC answers `TCCAccessPreflight` from a per-process cache, so the running app would otherwise keep seeing "not asked" until it restarts. Closing a tap within milliseconds of opening it cancels a pending prompt. When the requesting process exits, its prompt closes. The tap read can show its prompt even while the app is in the background.
- Unblocking audio QA without the user: re-sign the same build under a fresh identity instead of rebuilding (`PlistBuddy Set :CFBundleIdentifier`, plus `codesign --identifier`; app data follows `VOXFUSION_APP_ID`, not the bundle). macOS then asks again for every permission, so keep one build for a whole QA session. Detect a pending prompt by looking for an on-screen `UserNotificationCenter` window in `CGWindowListCopyWindowInfo`, and dismiss it by killing the requesting process. `tccutil reset All <id>` works without sudo only for bundles LaunchServices knows, for example after `lsregister -f` in `~/Applications`. `osascript ... activate` cannot bring another app to the front. A test helper that has gotten System Audio Recording once keeps it, so measure digitally with a per-process unmuted tap on the target device instead of asking again.
- Voice overlay positioning must use live monitor dimensions and the actual window position. Disconnecting an external display can leave the MacBook display at the same origin, so caching only the monitor origin misses the change. GPUI cannot hide, show or move a window, so `platform/overlay_window.rs` does it through the window's `NSWindow`; keep the frame math in logical (point) coordinates, which is what AppKit takes whatever the display's scale.
- Text in the interface goes through `ui::text::text(...)`, never a bare string child. GPUI's own text has no letter spacing, rounds line heights to whole pixels (`leading-relaxed` at 14px is 22.75px), wraps differently from CSS, and takes the baseline from the tallest fallback font in the line. `Text` shapes with GPUI but breaks lines by the Unicode line breaking algorithm, adds letter spacing per glyph, and places the baseline the way a browser does. Set sizes through `TypeScale` (`type_xs()`, `type_sm()`...) so the line height matches the design's scale. On GPUI's Linux text system a font's descent is negative; `Text` takes its absolute value.
- GPUI's `svg()` paints only with a color set on the element itself. `ui::widgets::icon(...)` inherits the surrounding text color like `stroke="currentColor"`.
- The 40px background grid is painted last, over the content, and skips the boxes marked with `above_grid(cx)`. That reproduces the original stylesheet, where the grid layer came first in the document and so painted above unpositioned content but below anything positioned after it. A card that should hide the grid needs the marker on a wrapper that spans its border.
- GPUI snaps layout to device pixels before layout runs and rounds the size a custom element measures up to a whole device pixel. Fractional CSS sizes can therefore land one device pixel away from a browser's rendering; a whole logical pixel of difference is a real layout difference.
- Layout differences from CSS that caused real mismatches: margins never collapse (an empty block between two spaced siblings takes a gap in GPUI and none in CSS); `flex: 1 1 0%` items start from their own padding and border, so two `flex-1` siblings with different padding are not equally wide (give the wrappers that basis explicitly); a scroll container's border must be on a wrapper outside it, or `scroll_to_item` and the scroll range are off by the border; an empty text element still takes a line, while an empty inline box in CSS takes none; a `<button>` centers its text, which only shows when the label wraps.
- GPUI stops applying hover styles after keyboard input until the pointer moves again. It also turns Enter/Space on a focused element with a click handler into a click on key up; an element that handles those keys itself must ignore `ClickEvent::Keyboard`, or the action runs twice.
- A global action handler (`cx.on_action`) reached from a key binding or a menu item runs while GPUI is updating the window that dispatched it. GPUI takes that window out of the app for the update, so `handle.update(cx, ...)` on it fails with "window not found" (which is why Cmd+W used to do nothing). Defer the window work with `cx.defer`, as the `CloseWindow` handler in `app.rs` does. On Linux, X11 then reports a visibility change for the closed window and GPUI logs a harmless `window not found` error.
- Shortcuts on Xvfb: `cmd-` bindings are Super on Linux. `xdotool search --onlyvisible --class voxfusion` also finds the dictation pill (200×56), often first, so pick the main window by size before focusing it. Send shortcuts through XTEST (`xdotool keydown super; xdotool key w; xdotool keyup super`); `xdotool key --window` sends synthetic events, which dispatched a shortcut twice in one test.
- `gpui-kit`'s text input treats a fully transparent caret color as unset and falls back to the text color. To hide the caret (fixture runs do), use a nearly transparent color.
- The design's CSS transitions run on `gpui_kit::base::motion::transition`, which moves a value towards a target known while rendering and already handles easing, reversal and reduced motion. Do not write another interpolation layer. `ui/motion.rs` only adapts it: `.transition_colors()` / `.transition_all()` on an element with an id make its colors (and opacity) fade whether a render or the pointer changed them, and must come before `.hover`, `.group_hover`, `.focus` and `.track_focus` in the chain, which then feed the transition instead of applying at once; `gliding(id, target, |value| element)` is for transforms (the switch knob, chevrons). Hover is only known at paint, so `Faded` resolves its target there, by asking a never-drawn `Div` that carries the hover styles for `compute_style` with the real element's hitbox. Fixture runs set `cx.set_reduce_motion(true)`, which snaps every transition; run a fixture with `VOXFUSION_FIXTURE_MOTION=1` to watch them play (record with `ffmpeg -f x11grab`).
- `gpui_kit::init` copies the system's Reduce Motion setting into `cx.reduce_motion()`. GPUI's `with_animation` then draws a static frame (the end of a one-shot animation, the start of a repeating one), and the kit's transitions snap.
- GPUI gives a window with `titlebar: None` a titled frame with the content drawn over it. macOS outlines a titled window with a hairline and rounds its corners, which shows as a faint box on a transparent window. `platform/overlay_window.rs` makes the dictation overlay borderless.
- The update archive keeps the format the Tauri builds published (`latest.json`, `VoxFusion.app.tar.gz`, minisign signature made with `tauri signer sign` and the same key), because installed copies update through it, and the executable keeps its old name `voxfusion-app`. `src/updater.rs` reads the same manifest and verifies with the same public key.
- A reqwest request with a timeout must be created inside the tokio runtime (`block_on(async fn)`), not passed in as an already-built future. `log::set_boxed_logger` needs `log`'s `std` feature, which this crate only gets through other dependencies; `logging.rs` uses `set_logger` with a leaked box instead.
